The default a tool falls back to when its arguments are not what it expects is part of its blast radius: a checker meant for a local preview whose argument parsing fails silently falls back to its live target. The protection is structural, the same as for a development configuration that resolves to a live machine: the live target is reached only by an explicit argument, never by a default.

## Evidence

A third carrier, same owner. A read-only checker of a deployed site, meant to run against a local preview first, went to production on its first run: its argument parser skipped the first argument whenever an optional flag was absent, so the preview's address was dropped and the default, the live site, was used. It only read the public site, so nothing changed; it was fixed before the next run.

What admission still needs: a carrier of another owner. The queued candidate's mechanism is the same; this adds the form in which a failed parse falls back to the live default.
