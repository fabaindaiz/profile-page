A pre-commit gate reproduces the commit only when it runs on what is staged, not on the working tree: files left unstaged or untracked make it pass a commit that fails alone, or refuse one that is fine. The working tree is the replica the note warns about, at the scale of one commit.

## Evidence

One carrier, three forms in one day. A pre-commit hook gated the disk, not the index, found by a fresh review; it now gates a copy of the index, and was seen to refuse a fault present only in the index and to pass one present only on disk. A commit with a pathspec ran the hook against a temporary index, and the gate failed on it. Splitting one fix out of a larger change, the gate read a new untracked file in the working tree and a document-path audit refused the commit; stashing with the index kept and untracked files included let it see exactly the staged commit.
